# MeshNet — Hints

> Each tier costs score points. Only request when genuinely stuck.

## Tier 1 — Conceptual Direction (-5% score penalty)
Think of this problem as two interleaved challenges: **topology management** (keeping the routing graph connected as nodes fail and energy depletes) and **data plane efficiency** (moving sensor readings to gateways with minimal energy per bit). The key insight is that these have opposing incentives — the most reliable topology uses many redundant paths (high energy cost) while the most efficient topology uses a single minimum-energy spanning tree (low resilience). A well-designed protocol explicitly trades these off: use a tree for normal operation, and trigger local repair only when a tree edge dies. OTA updates have a third constraint — you need gossip-style epidemic dissemination to reach nodes that are temporarily unreachable.

## Tier 2 — Technique Guidance (-10% score penalty)
- **Radio model**: Use the **log-distance path loss model**: `RSSI_dBm = P_tx_dBm - 10 * n * log10(d / d0)`. A link is considered "viable" if `RSSI > sensitivity_threshold` (e.g., -100 dBm). Model `n = 2.7` for open farmland, `d0 = 1 m`.
- **Routing**: Implement **RPL (IPv6 Routing Protocol for Low-Power and Lossy Networks)** concepts simplified: each node maintains an "objective function value" (OFV) based on hop count + ETX (Expected Transmissions). Parent selection: pick the neighbour with the lowest OFV. When a parent goes silent for 3 beacon intervals, trigger a DIO (DODAG Information Object) broadcast to find a new parent.
- **Data collection**: Use **Trickle timer** for DIO broadcasts (exponential back-off between beacons when the network is stable, rapid re-broadcast when topology changes). For data forwarding, store-and-forward with a **priority queue** (critical sensor readings first).
- **Energy model**: Transmit = 50 mA × V_bat × t_tx; Receive = 25 mA × V_bat × t_rx; Sleep = 0.01 mA × V_bat × t_sleep. Use 3.3 V. Track `battery_j` per node; set node as dead when battery_j <= 0.
- **Fault tolerance under 50% failure**: When simulating random failures, ensure at least 2 disjoint paths exist from every node to a gateway (use Menger's theorem to check k-connectivity). In the routing protocol, keep a backup parent (the second-best OFV neighbour) and switch immediately on primary parent loss.
- **OTA updates**: Use **epidemic (gossip) dissemination** — when a node receives a firmware chunk it does not have, it re-broadcasts it to all neighbours. Use a **bitmap** to track which chunks have been received; a node is "complete" when all bits are 1. This achieves 95%+ delivery in sparse networks even with 30% packet loss.

## Tier 3 — Implementation Guidance (-15% score penalty)
1. **Node class** (`node.py`): `class SensorNode`: fields `node_id`, `x_m`, `y_m`, `battery_j`, `is_gateway`, `is_dead`, `parent_id`, `ofv`, `routing_table: Dict[int, int]`, `firmware_bitmap: List[bool]`. Methods: `transmit(payload_bytes, target_node) -> bool`, `receive(packet) -> None`, `sleep(duration_s) -> None` — each adjusts `battery_j`.
2. **Radio model** (`radio.py`): `def link_quality(node_a, node_b, config) -> float`: compute distance, apply path loss formula, return SNR; `def transmission_succeeds(snr, config) -> bool`: Bernoulli trial with success probability `min(1, snr / threshold)`.
3. **Routing engine** (`routing.py`): `class RPLRouter`: `compute_routing_tree(nodes, gateways) -> Dict[int, int]` (node_id -> parent_id). Implement Dijkstra with ETX edge weights. `repair_route(dead_node_id, nodes) -> None`: detach dead node's children and re-attach them using BFS from gateways.
4. **Simulation loop** (`simulator.py`): discrete-time loop over `simulation_steps`. Each step: (a) apply random node failures at `failure_rate`, (b) each alive node generates one sensor reading and queues it, (c) run one round of store-and-forward along routing tree, (d) run one OTA dissemination round, (e) update battery budgets. Log delivery rate, latency, energy per message every 100 steps.
5. **OTA dissemination** (`ota.py`): `class OTAManager`: split `firmware_payload.bin` into 128-byte chunks; start by giving all chunks to gateway nodes; each simulation step, nodes with chunks broadcast them to neighbours; track delivery completion per node; stop when all alive nodes have full firmware or 10x network diameter steps have passed.
6. **Benchmark runner** (`run_benchmarks.py`): for `num_nodes` in [100, 1000, 10000], generate a random topology (uniform random placement in area_km2), run simulator for 1000 steps, extract metrics, append to `simulation_results.json`.
7. **Protocol spec** (`protocol_spec.md`): describe (a) beacon/DIO format and timing, (b) parent selection objective function, (c) route repair trigger condition, (d) OTA chunk dissemination algorithm, (e) energy accounting model. Aim for ~2 pages with ASCII diagrams of packet formats.
