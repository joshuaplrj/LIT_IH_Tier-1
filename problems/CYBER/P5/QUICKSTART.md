# Zero-Day Factory — Quick Start

## Objective
Build an automated vulnerability discovery pipeline that finds memory corruption bugs in 5 stripped x86-64 ELF binaries (no source code, no debug symbols) and produces at least one working proof-of-concept exploit per binary.

## Inputs
- `binaries/` — Directory containing 5 ELF executables: `bin1`, `bin2`, `bin3`, `bin4`, `bin5`
- Each binary is a networked service; consult `ports.json` for the port each binary listens on
- ASLR is disabled on the evaluation machine (`/proc/sys/kernel/randomize_va_space` = 0)
- No source code, no debug symbols (stripped with `strip`)

```json
// ports.json
{
  "bin1": 9001,
  "bin2": 9002,
  "bin3": 9003,
  "bin4": 9004,
  "bin5": 9005
}
```

## Expected Output
Directory `submission/` containing:
- `submission/vulnerability_report.json` — structured bug report
- `submission/exploits/bin1_exploit.py` through `bin5_exploit.py` — working PoC scripts
- `submission/metrics.json` — performance metrics

```json
// vulnerability_report.json
{
  "binaries": [
    {
      "binary": "bin1",
      "vulnerabilities": [
        {
          "vuln_id": "BIN1-001",
          "type": "buffer_overflow | use_after_free | format_string | integer_overflow | heap_overflow",
          "location": "0xdeadbeef",
          "function_name": "...",
          "severity": "Critical | High | Medium",
          "exploitable": true,
          "description": "..."
        }
      ]
    }
  ]
}
```

## Recommended First Steps
1. Disassemble all 5 binaries with Ghidra (headless mode) or `rizin -q -c 'aaa; afl' bin1` to get a function list and identify functions that handle network input (look for `recv`, `read`, `fgets`, `gets`, `scanf` xrefs).
2. Run AFL++ in `QEMU` mode against each binary in parallel: `afl-fuzz -Q -i corpus/ -o findings/bin1 -- ./bin1` — AFL requires no source code in QEMU mode and will find many crash inputs within 20–30 minutes.
3. For each crash input generated by AFL, use GDB with the `checksec` and `pwndbg` plugins to classify the crash (segfault at a controlled address = buffer overflow, invalid free = use-after-free, format string = `%n` write in `printf`).

## Scoring Breakdown
| Metric                              | Weight |
|-------------------------------------|--------|
| Bugs found (count and type variety) | 40%    |
| Exploit quality (controlled hijack) | 35%    |
| Report quality                      | 25%    |

## Common Pitfalls
- AFL++ in QEMU mode is 5–10x slower than instrumented mode — start it immediately at the beginning of the hackathon and let it run while you do manual analysis.
- `gets()` and `strcpy()` without bounds checks are trivially exploitable — `objdump -d bin1 | grep -E 'call.*gets|call.*strcpy'` takes 10 seconds and finds the lowest-hanging fruit.
- With ASLR disabled, a simple `ret2libc` (return to `system("/bin/sh")`) is sufficient for a working PoC — you do not need a full ROP chain unless NX is enabled (check with `checksec --file=bin1`).
